03 · Veyrin · Native macOS

Veyrin.

Veyrin is my experimental native macOS app. It started as an unofficial Character.AI client, and now also runs chats against local Ollama models and my own cloud API keys.

SwiftSwiftUImacOSRESTWebSocketsOllamaKeychain
Experimental · v0.1.1

A native Mac app, not a web wrapper.

The app is split into SwiftUI views, view models and services. Character.AI runs through its own REST and WebSocket layer, because there’s no public API for third-party clients. Local and cloud chat use a separate provider layer that lists models and streams text over HTTP.

That split is deliberate. Character.AI keeps candidates, pins, edits and rewind, while Ollama and the cloud providers only have to stream a reply. Forcing both through one generic conversation API would have cost the Character.AI features.

Sign-in uses a session token, which the app checks before saving it in the macOS Keychain. Cloud API keys are separate Keychain items. Provider requests use an ephemeral session with no cookies, cache or redirects, and only the endpoint you picked receives the chat.

Character.AI doesn’t offer a public API for third-party clients, so Veyrin uses undocumented endpoints. They can change without notice, and using an unofficial client may put your account at risk.

What it can do.

  • Pick Character.AI, local Ollama models or a configured cloud provider at launch, and switch without restarting
  • Stream Character.AI replies, switch responses, edit, pin or rewind
  • Test an Ollama endpoint and choose an installed model. Veyrin never downloads models
  • Add Claude, OpenAI Responses, Chat Completions or an OpenAI-compatible endpoint, with its key in the Keychain
  • Save provider chats per provider, model and character, then reopen them from the conversation sidebar
  • Search chat history, browse recent chats and load older messages
  • Save Discover characters to a local library, with search, editing and export
  • Export Character.AI personas as JSON or Markdown, import character cards and use a persona in a local or cloud chat
  • Discover recommended characters, popular lists and curated scenes, then open profiles and similar characters
  • Browse the feed, posts and creator profiles
  • Change wallpaper, glass and avatar settings, and check GitHub releases from Settings
  • Stage image attachments for preview. Sending images isn’t supported yet.

What it keeps on the Mac.

Saved characters, library edits, imported personas, provider chats and the image cache are plain JSON and files in Application Support. They stay on disk after you sign out, and they aren’t encrypted.

Because those are plain local files, saving characters and chatting with Ollama keep working without a connection. Character.AI history is still fetched per request, so that side needs a network.

It’s still early.

This is an experimental release, and the Character.AI endpoints it uses are undocumented. Character search needs the web-next-auth cookie from a signed-in browser; suggestions, Discover and similar characters work without it. Chat history still needs a connection, cloud chat is text only, and image attachments can be previewed but not sent.

Provider chats live only on this Mac and nothing migrates between providers. The build is ad-hoc signed rather than notarised, and it doesn’t install updates.
